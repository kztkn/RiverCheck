# 本日のハンド・マッチボーナス

- ステータス: アイデア・要件確認待ち
- 最終更新: 2026-08-09
- 対象: 開催への参加、写真、結果順位

## アイデア概要

参加者が開催へ参加したとき、その開催限定の「本日のハンド」を2枚配る。

同じ開催で、カードのランクだけでなくスートまで完全に同じ2枚のハンドを引いた参加者が現れた場合、記念写真を残すルールとする。

ハンドが一致した対象者は、開催終了時の成績へ+300BBのボーナスを適用できる。これにより、実際の残りチップだけでは下位でも上位入賞する可能性が生まれる、ネタ・イベント性のある仕組みにする。

## 現時点で残す要件

- 本日のハンドは参加時に配る
- 1人につき2枚のカードを配る
- 開催ごと・参加者ごとにハンドを固定する
- 参加取消や再参加でハンドを引き直せないようにする
- 一致判定はランクとスートの完全一致とする
- 2枚の並び順が異なっても、同じ組み合わせなら一致として扱う案を優先する
- 同じハンドの参加者が現れたら、その開催で記念写真を残す
- 一致した対象者は結果へ+300BBのボーナスを適用できる
- ボーナスによって最終順位・上位入賞が変わり得る

## 配布方式の前提

通常の1デッキから重複なしで配る方式では、スートまで完全一致する2枚のハンドは複数人へ配れない。

そのため、この機能では参加者ごとに独立して52枚から2枚を抽選する「デジタルくじ方式」を前提候補とする。同じ開催内でも別参加者が同じカードを引ける。

ハンドはサーバー側の安全な乱数で決定し、DBへ保存する。画面再読み込み、別端末表示、参加取消・再参加で再抽選しない。

## 画面案

### 参加時

- 参加完了後に「本日のハンド」をカード2枚で表示する
- ♠・♣は暗色、♥・♦は赤系など、カードとして直感的に読める表示にする
- ハンドが固定済みの場合は、再訪時にも同じカードを表示する

### ハンド一致時

- 「ハンドが一致しました！」という特別表示を出す
- 一致した参加者名を表示する
- 「記念写真を残そう」と案内する
- 写真登録済みの場合は結果画面のハイライトと一緒に表示する案を検討する

### 結果確定時

- 実チップから算出した損益BBと、ハンドボーナス+300BBを区別して表示する
- 例: `実績 +80BB / HAND BONUS +300BB / 順位判定 +380BB`
- ボーナス適用者が分かる小さなカード・スートアイコンを表示する

## 重要な設計論点

### +300BBとチップ検算

実際のチップへ+300BB相当を加えると、参加者から報告されたチップ総量と一致しなくなる。

そのため、次の値を分ける案を優先する。

- `actual_net_bb`: 実チップから算出した通常の損益BB
- `hand_bonus_bb`: ハンド一致によるボーナス。対象者は300
- `ranking_bb`: 順位判定用。`actual_net_bb + hand_bonus_bb`

チップ総量検算は従来どおり実チップだけで行い、最終順位は`ranking_bb`で決める。会費の順位別負担額も、このボーナス反映後順位を使う想定とする。

ただし、個人戦績の累計損益BBへボーナスを含めるかは実装前に確認する。

### 写真との関係

既存仕様は1開催につき開催写真1枚である。

ハンド一致写真を既存の開催写真として扱うか、この機能専用の写真枠を追加するかは未決定。単なる現地ルール・案内だけにして、アプリ上の写真必須判定を設けない選択肢もある。

### ボーナス適用の確定方法

一致はDB上のハンドから自動判定可能だが、写真撮影をボーナス条件に含めるかは未決定。

- ハンド一致だけで自動的に+300BB
- 写真登録を主催者が確認した場合だけ+300BB
- 主催者が最終確定画面でボーナス適用をONにする

MVPでは、誤操作を避けるため主催者が確定画面で対象者と+300BBを確認する方式が候補。

## データ設計案

過剰設計を避けるなら、開催参加者へ配布カードとボーナス状態を保持する。

### game_participantsへの追加候補

- `daily_card_1`: `AS`、`10H`等の正規化コード
- `daily_card_2`
- `hand_bonus_bb`: デフォルト0
- `hand_bonus_confirmed_at`: nullable

確定結果には、確定時点の監査可能なスナップショットとして次を保持する案を検討する。

- `actual_net_bb`
- `hand_bonus_bb`
- `ranking_bb`
- 配布ハンド、または参加者レコードへの参照

訂正機能でも通常のチップ値とハンドボーナスを区別して履歴へ残す。

## 不正・引き直し対策

- ハンドはクライアントではなくサーバーで生成する
- 同じ開催・同じ`group_player`には一度だけ配る
- 参加取消後も配布履歴を消さない
- 同じ名前で再参加しても既存ハンドを再利用する
- 画面更新やCookie削除で再抽選できないよう、`game_id + group_player_id`を基準にする
- 管理者が任意のカードへ変更する機能はMVPでは設けない

## 実装前に確認する項目

1. +300BBは一致した参加者全員へ適用する認識でよいか
2. ボーナスは自動適用か、主催者確認後の適用か
3. 写真撮影・登録をボーナス取得の必須条件にするか
4. 既存の開催写真1枚を使うか、専用写真枠を追加するか
5. 個人戦績の累計・平均損益BBへ+300BBを含めるか
6. LINE共有結果では実績BBとボーナスをどう表記するか
7. 3人以上が同じハンドになった場合も全員を対象にするか
8. ハンドを本人だけに見せるか、参加直後から全員へ公開するか

## 完了条件案

- 参加時に2枚のハンドが一度だけ安全に配布される
- 再読み込み・再参加でも同じハンドが表示される
- ランク・スート完全一致を正しく判定できる
- 一致時に参加者・主催者へ分かりやすく通知される
- 実チップ検算と+300BBボーナスが混ざらない
- ボーナス反映前後の値を結果画面で確認できる
- ボーナス反映後順位で会費を精算できる
- 結果訂正・監査履歴でもボーナスが追跡できる
- 写真ルールが結果画面のハイライト導線と矛盾しない
- 抽選・一致判定・順位加算へunit testがある
