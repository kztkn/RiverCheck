# 業務ルール

## 数値の共通ルール

チップ、リバイ回数、金額は JavaScript の safe integer 範囲の整数として扱う。入力値は原則 0 以上とし、小数、`NaN`、無限大、safe integer 範囲外は拒否する。BB換算の基準となる初期チップだけは1以上とする。会費精算の想定参加人数は4人以上とする。

## 点数

```text
score = remaining_chips - settlement_rebuy_count × rebuy_chips
```

点数は負になり得る。入力である残チップ、リバイ回数、リバイチップは 0 以上とする。

## 損益BB

リングゲームは初期チップを常に100BBとして扱う。確定結果、共有文、個人戦績では保存済みの整数`score`から初期チップを差し引いた「損益BB」を表示する。

```text
chips_per_bb = initial_chips / 100
net_bb       = (score - initial_chips) / chips_per_bb
             = (score - initial_chips) × 100 / initial_chips
```

初期チップ20,000の場合は1BB=200チップとなり、40,000点は+100BB、20,000点は0BB、10,000点は-50BBとなる。表示は正数に`+`、負数に`-`を付け、0は符号なしとする。小数は最大小数第2位とし、不要な末尾の0は表示しない。確定結果では損益BBの正数を緑、負数を赤、0をニュートラル色で表示する。順位判定とDB保存は誤差を避けるため従来どおり整数`score`を使用し、BB値では順位を計算しない。

## 順位

次の順に並べ、1 から連番の順位を付ける。共同順位は作らない。

1. `score` の降順
2. `total_rebuy_count` の昇順。過去データでNULLの場合だけ`settlement_rebuy_count`を代用
3. 完全同点は `group_player_id` の Unicode 辞書順（昇順）

3 番目は人の優劣を表すルールではなく、結果を常に再現可能にするための決定的 tie-break である。後から別ルールへ変更できるよう `calculateRanking` 内に閉じ込める。

## チップ総量検算

```text
expected_total = initial_chips × participant_count
               + rebuy_chips × total_settlement_rebuy_count

reported_total = sum(remaining_chips)
difference     = expected_total - reported_total
```

`difference = 0` を一致とする。正数はチップ不足、負数は報告過多を意味する。差があっても主催者は警告を確認したうえで finalize できる。未入力者がいる間は、その参加者の残チップと終了時リバイ証を0として暫定値を表示するが、全員が入力するまで finalize は許可しない。

## 会費精算

### 精算総額

`venue_cost` を固定の100円単位で切り上げる。丸め単位は利用者が変更できる設定にしない。

```text
settlement_total = ceil(venue_cost / 100) × 100
```

保存する全順位の負担額は0以上の100円単位とし、`1位 <= 2位 <= ... <= 最下位`でなければならない。同額は許可する。全順位の合計が`settlement_total`と一致しない配分は保存・finalizeできない。

### おすすめ配分の生成

標準・ゆる傾斜のおすすめは、従来の上位3位を起点にした配分計算で全順位を生成する。1〜3位はおすすめ額で固定し、4位以下が3位より安くならないよう、まず3位の負担額を4位以下全員の最低額として確保する。

```text
minimum_required = first_place_cost
                 + second_place_cost
                 + (participant_count - 2) × third_place_cost
```

`minimum_required > settlement_total` の設定は成立しないため拒否する。残額 `settlement_total - minimum_required` を、4位以下の順位ウェイト `1, 2, ..., N-3` で次のように配分する。

1. 4位から最下位の1つ前までは、`third_place_cost + floor_100(残額 × 順位ウェイト / ウェイト合計)` とする
2. 100円未満を切り捨てた差額を含め、最下位は `settlement_total - 最下位以外の合計` とする
3. 全員の負担合計を `settlement_total` と必ず一致させる

この方法では4位は必ず3位以上となり、以降も順位が下がるほど負担が減らない。同額は許可する。これはGoogleスプレッドシート `poker_ranked_cost_sharing` の「精算シート」タブと同じ計算式である。

シンプル割り勘は全員の均等額を100円単位で切り上げ、精算総額を超える分だけ上位を安くする。通常は1位だけを安くし、会費が小さく1位だけでは調整できない場合もマイナスを避けるため、最下位から順に切り上げ後の均等額を充当する。

```text
common_share = ceil(settlement_total / participant_count / 100) × 100
```

表彰台ボーナスは6人以上を対象とし、順位ごとの配分ウェイトを`0, 0.50, 0.75, 1.20, 1.25, ...`とする。4位以下は順位ごとに0.05増やし、1.40を上限とする。精算総額をウェイト合計で正規化して100円単位で切り捨て、残った100円口は4位以下の最下位から上位へ順に加算する。これにより1位を0円に保ち、2・3位を優遇しながら4位以下をなだらかに傾斜させる。

プレビューは「上位3位から配分」と「全順位を個別調整」を切り替えられる。上位3位から配分では1〜3位の変更を起点に4位以下を従来式で再生成する。4位以下を編集すると個別調整へ切り替わり、以後は他順位を自動補正しない。標準・ゆる傾斜のおすすめは上位3位から配分へ戻し、表彰台ボーナス・シンプル割り勘は全順位を個別調整へ切り替える。会費変更と想定人数変更では、現在選択中のおすすめモードで全順位を再生成する。表彰台ボーナス選択中に人数が6人未満になった場合は、標準傾斜へ切り替える。

新規または精算設定更新後の開催は全順位を`games.cost_shares`へ保存し、finalizeと結果訂正で使用する。移行前の`cost_shares IS NULL`の開催だけは、互換性のため保存済み1〜3位から従来式で全順位を算出する。

### 3人以下

順位別傾斜精算は4人以上を前提とするため設定不可とする。

## 日時

開催条件では日付だけを入力し、時刻は扱わない。今回の利用グループを日本国内と仮定し、入力日付の Asia/Tokyo（UTC+09:00）午前0時として `TIMESTAMPTZ` に保存する。複数タイムゾーン対応時はグループへ IANA time zone を追加する。

## リバイ記録

ゲーム中のリバイは、累計回数と現在の未返済口数を分ける。

- `total_rebuy_count`: リバイで1増え、100BB返済では減らない
- `outstanding_rebuy_count`: リバイで1増え、100BB返済で1減る
- `settlement_rebuy_count`: 終了時に実物のリバイ証を数えて入力する精算値

通常操作では`0 <= outstanding_rebuy_count <= total_rebuy_count`を維持する。参加者と主催者の操作はイベント履歴とカウンターを同一トランザクションで更新する。結果入力後は通常のリバイ・返済操作を止め、必要な訂正は主催者の修正操作で行う。

現在スタックは保存・自動判定しない。未返済がある参加者は、ポット精算後のスタックが150BBを超えた場合に任意で100BBを返済でき、300BBを超えた場合は100BBを返済する。返済後も300BBを超え、かつ未返済が残る場合は同じ条件を繰り返す。参加者画面ではルールを必要時だけボトムシートで確認し、本人が返済を記録する。

スコアとチップ総量は返却済み100BBを再加算しないよう`settlement_rebuy_count`を使う。統計と同点順位には`total_rebuy_count`を使う。終了時の`outstanding_rebuy_count`と`settlement_rebuy_count`が異なる場合は主催者へ警告し、差を明示確認した場合だけ確定できる。`settlement_rebuy_count > total_rebuy_count`は確定できない。

過去の`rebuy_count`から返済済みリバイは復元できないため、移行前の確定結果の`total_rebuy_count`はNULL（不明）とし、正確な累計統計へ含めない。移行時点で受付中の開催は、入力済みの`settlement_rebuy_count`を累計・未返済の初期値とし、既に返済済みの回数がある場合は主催者が救済修正する。

## ローカルルール

参加者画面の「ローカルルールを確認」は、100BB返済ルールと開催固有ルールを同じボトムシートへ表示する。72oボーナスがONの開催では、7と2のオフスートでポットを獲得したプレイヤーが、ほかの参加者全員から2.5BBずつ受け取る。スートが同じ72sは対象外とする。

`games.seven_deuce_rule_enabled`は開催ごとの適用有無だけを保持する。新規開催は初期ON、導入前の既存開催はOFFとし、主催者は`open`中だけ切り替えられる。`finalized`後は設定を変更しない。RiverCheckはルールを参照表示するだけとし、72oの成立判定、対象者、支払い、チップ増減は自動記録しない。

## チップ設定

`rebuy_chips` は常に `initial_chips` と同じ値にする。画面ではリバイチップを個別設定せず、初期チップの変更をリバイにも反映する。

## TABLE STORIES

- 参加者投稿は`game_participant`へ紐づき、1参加者・1開催につき最大1件とする
- 本文は前後空白を除去し、空文字は未入力として扱う。最大160文字とする
- 本文または写真のどちらかがある場合だけ投稿行を保持し、両方を外した場合は本人投稿行を削除する
- `open`中の作成・更新・削除は、終了時の残りチップ・リバイ証保存と同じPostgreSQLトランザクションで処理する
- `finalized`後も、その開催へ参加した本人は投稿だけを追加・更新・削除できる。確定済みの残りチップ、リバイ証、結果は変更しない
- `open`中の投稿は本人と主催者以外へ公開しない。`finalized`になった時点で未削除の投稿を開催詳細へ公開する
- 主催者を含む全投稿は実在する参加者へ紐づけ、同じカードUIで投稿作成時刻の古い順に並べる。固定の主催者名義は作らない
- 主催者削除は開催確定後も許可し、本文と写真参照を消したsoft deleteとする。`deleted_at`と`deleted_by_type = organizer`を保持する
- 投稿写真は本文と独立して任意とし、JPEG・PNG・WebP、圧縮後3MB以内、長辺1,800px以内を共通ハイライト規則で扱う

## 精算プレビュー

開催作成・編集時は、想定参加人数と会費からおすすめの全順位負担額を生成して表示する。金額表示をタップした順位だけ入力状態へ切り替え、全順位を直接編集できる。

- finalizeはプレビューで保存された全順位配分をそのまま使う
- 想定参加人数は金額確認用であり、参加者を事前登録しない
- 新規作成時の想定人数を保存し、参加人数の増減では自動変更しない
- open中は想定人数を手動変更できる
- 想定参加人数は手動変更でき、ドタ参加・ドタキャン後の金額を試算できる
- venue_costまたは想定人数を変更した場合は、現在選択中のおすすめモードで全順位を即時再生成する
- 上位3位から配分では、1〜3位の変更に合わせて4位以下を自動再配分する
- 全順位を個別調整では、変更した順位以外を動かさず、100円単位、順位傾斜、合計一致をリアルタイム検算する
- 全順位を順位ごとの金額パネルで表示し、同じ内容の文章要約は重複表示しない

### おすすめ配分

おすすめ配分は、ボタンを押した時点で全順位のプレビューへ即時反映する。反映後は各順位を直接編集できる。

- 標準傾斜: 精算総額を順位ウェイト `1, 2, ..., N` で按分する
- ゆる傾斜: 均等割を2/3、標準傾斜を1/3混ぜた配分を目標とし、既存の精算条件でその目標に最も近い上位3人の金額を選ぶ。少人数や初心者が多い会で順位差を小さくする
- シンプル割り勘: 全員分を100円単位で切り上げ、合計超過分だけ上位を安くする
- 表彰台ボーナス: 6人以上で1位を無料、2・3位を優遇し、4位以下へ最大1.40の配分ウェイトを付ける

標準・ゆる傾斜は上位3人の理論額を100円単位で切り捨て、既存の精算ロジックで全順位を算出する。表彰台ボーナス・シンプル割り勘は上位3人を起点にせず全順位を直接算出する。配分モード自体は保存せず、反映後または手動調整後の全順位金額を保存する。

おすすめ反映時の人数は `max(想定人数, 現在の参加人数, 4)` とする。現在の参加人数が想定人数を超えた場合は、想定人数も現在の参加人数へ更新し、その旨を画面に表示する。

## 確定後の結果訂正

結果訂正は主催者だけが実行でき、gameのstatusは`finalized`から変更しない。対象参加者集合、初期チップ、会費設定は固定し、既存参加者の残りチップとリバイ回数だけを変更できる。

訂正後も通常のfinalizeと同じ`calculateFinalResults`を使用し、score、順位、会費負担額を全参加者分再計算する。入力変更のない参加者でも順位または会費が変わった場合は訂正差分へ含める。

訂正前後の全確定結果をスナップショットとして保存してから現在結果を置換する。履歴保存、game_participants更新、game_results置換は同一トランザクションとし、途中失敗時はすべてrollbackする。変更がない訂正は拒否する。

## プレイヤー実績

実績はグループ内の確定済み`game_results`だけから判定し、`group_player`単位で獲得する。受付中の参加・入力・リバイ状態は条件に使わない。連続条件は本人が参加した確定済み開催だけを開催日時順に並べ、本人が不参加の開催は連続性へ影響させない。損益条件は個人戦績と同じ`(score - initial_chips) / initial_chips * 100`の損益BBを使い、プラス収支は0BBを含めず`net_bb > 0`とする。

実績は次の16件とする。

- 初戴冠: 初めて1位を獲得
- またお前か: 通算3回優勝
- いつメン: 5開催に参加
- テーブルの主: 10開催に参加
- 一撃必殺: 1開催で+300BB以上
- ダイヤの原石: 累計損益+100BBへ到達
- ファーストハンド: 初めて確定済み開催へ参加
- 不死鳥: リバイ累計1回以上の開催で1位
- 生還: リバイ累計1回以上の開催をプラス収支で終了
- 借りたものは返す: リバイ累計1回以上、終了時未返済0口、手元のリバイ証0枚で終了
- ノーダメージ: 本人の参加開催で3開催連続リバイ0回
- 三日天下: 1位の次の参加開催で最下位
- 下剋上: 最下位の次の参加開催で1位
- 4位のプロ: 参加者4人以上の開催で通算3回4位
- 銀メダル収集家: 通算3回2位
- 王座防衛: 本人の参加開催で2開催連続1位

条件を満たす最初の確定済み開催を`source_game_id`として記録する。同じ実績は`group_player`ごとに一度だけ保持し、1開催で複数条件を満たした場合はすべて獲得する。

確定結果を訂正した場合は、そのプレイヤーの現在の正式な確定履歴全体から実績を再評価する。訂正後もいずれかの正式な開催で条件を満たす実績は保持し、成立しなくなった実績は削除し、新たに成立した実績は追加する。連続条件など訂正開催より後の履歴へ波及する条件も再評価する。削除対象を装備中なら装備を解除する。プロフィールへ装備できるのは本人が同じ`group_player`で現在獲得済みの実績1件だけとし、未装備へ戻すこともできる。

## ランキング指標

ランキングの「最近」は本人が参加した確定済み開催を開催日時の新しい順に最大3件取得し、その平均損益BBで順位付けする。3件未満は存在する開催だけで平均し、調子を表す定性的なラベルは付けない。

TOP3回数は確定結果で3位以内に入った開催数とし、個人詳細のTOP3率は`TOP3回数 / 参加回数 * 100`とする。個人詳細のプラス収支率は`net_bb > 0`の開催数を参加回数で割って100を掛け、0BBはプラスへ含めない。平均順位率は開催ごとに`rank / participant_count * 100`を求め、そのプレイヤーの参加開催で平均する。平均順位率だけは値が低いプレイヤーを上位とする。
